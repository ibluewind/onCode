## 슬라이스 1 — 서버 골격과 워크플로 영속

### 구현 내용

중앙 서버를 modular monolith로 두고, 공식 워크플로 상태를 프로세스 메모리가 아니라 PostgreSQL에 둔다. 에이전트 본문·Tool Gateway 실호출·실추론은 하지 않았다.

#### 동작

1. **기동**
   - Spring Boot 4.1.1, Java 25.
   - 패키지 모듈 8개: `api`, `workflow`, `context`, `toolgateway`, `agentruntime`, `inferencegateway`, `approval`, `persistence`.
   - 개발 DB: `infra/docker-compose.yml`의 `oncode-postgres` (`127.0.0.1:5437`, DB/스키마/사용자 `oncode`). CodeGEN 5434와 분리.
   - 앱 기동 시 Flyway가 스키마 `oncode`에 V1을 적용한다.

2. **DDL (`V1__work_item_workflow.sql`)**
   - `work_item` — 요청 단위. `WI-...`
   - `workflow` — SSOT. `current_state`, `revision`, `lease_owner`, `lease_until`
   - `workflow_transition` — 허용된 전이 한 행
   - `context_entry` — `context_ref` PK, `payload` jsonb
   - 테이블·컬럼에 `COMMENT ON` 있음

3. **명시적 전이 (`WorkflowEngine` + `WorkflowTransitions`)**
   - 1일차 선형 경로만 허용:
     `RECEIVED → CLASSIFYING → DISCOVERING_CONTEXT → DESIGNING → WAITING_DESIGN_APPROVAL`
   - `receive`: Work Item + Workflow를 `RECEIVED`/`RUNNING`으로 insert, 리스를 이 노드가 잡음
   - `transition`: 그래프에 없으면 상태 불변 + `IllegalWorkflowTransitionException`. `WAITING_*`에 들어가면 `status=WAITING`, 리스 해제
   - `receiveAndDriveToWaitingDesignApproval`: 에이전트 없이 선형 경로만 돌림 (1일차 뼈대)
   - `resumeAfterRestart`: DB에서 다시 읽음. WAITING이면 리스를 잡지 않음
   - `tryAcquireLease`: RUNNING이고 리스가 없거나 만료면 회수. WAITING은 거부
   - 갱신은 `revision` 낙관적 잠금. 충돌 시 `WorkflowConcurrentModificationException`

4. **Context (`ContextService`)**
   - `put(workItemId, refType, payloadJson)` → `ctx://work-items/{id}/{type}/latest` (같은 타입 latest는 upsert)
   - `get(contextRef)` → JSON 본문. 없으면 `ContextNotFoundException`
   - `context.query`·검색은 없음

5. **영속 방식**
   - JPA 없음. Spring JDBC `JdbcClient` + Flyway.
   - Maven은 `.mvn/settings.xml`로 Maven Central만 사용. 로컬 Nexus(`127.0.0.1:8081`) 미사용.

## 슬라이스 2 — 설계/코드 승인

### 구현 내용

WAITING_*에서 빠져나가는 유일한 길은 승인 결정이다. 설계 승인과 코드 승인은 서로 다른 `approval` 행이며, 한 번 쓰면 재사용할 수 없다. Local Agent `apply`는 호출하지 않는다.

#### 동작

1. **Flyway V2** `approval` — SPEC-03 필드 + `is_consumed`. 종류는 `DESIGN` / `CODE_CHANGE`. REQUESTED는 워크플로당 종류별로 하나(부분 unique index).
2. **`ApprovalPort` / `ApprovalService`** — request, requireUsable, consume. REST 없음.
3. **전이**
   - 설계 승인: `WAITING_DESIGN_APPROVAL` → `IMPLEMENTING`
   - 설계 거절: → `REJECTED` (`status=FAILED`). IMPLEMENTING 없음
   - 코드 승인: `WAITING_CODE_APPROVAL` → `APPLYING_CHANGE` (상태만, apply 없음)
   - 코드 거절: → `REJECTED`. APPLYING_CHANGE 없음
   - `transition()`은 WAITING 탈출 거부
4. **선형 스텁** IMPLEMENTING → REVIEWING → PREPARING_CHANGE → WAITING_CODE_APPROVAL (에이전트 없음)
5. **fail-closed** 재사용, 만료, 타입/리소스 불일치 시 예외. 워크플로 행은 그대로

PHASE_02가 SPEC-02의 `ANALYZING_DEPENDENCY`를 스텁 허용하므로 설계 승인 다음은 `IMPLEMENTING`이다.

## 슬라이스 3 — Tool Gateway · Agent Runtime · Inference Gateway

### 구현 내용

IDE 없이 PHASE_02가 허용한 인프로세스 하니스와 스크립트 Inference로 Design → Approval → Implementation mock 루프를 닫는다. 서버는 워크스페이스 파일을 열지 않고, 에이전트는 apply를 부르지 않는다.

#### 동작

1. **Inference Gateway** — `ModelProfile`만 받는다. 구현은 `ScriptedInferenceGateway` (실 vLLM 없음). 에이전트는 이 인터페이스만 호출.
2. **Agent Runtime** — Senior / Implementation / Review 정의. `AgentTurn`에는 `context_ref`만 있고 payload 필드가 없다. 결과는 `context.put`.
3. **Implementation** — `workspace.propose_changes`만 허용. `workspace.apply_changes`는 정의에 없음.
4. **Tool Gateway** — ToolRequest 매핑, `call_id` 상관, timeout 시 status=TIMEOUT + retryable ToolError. AGENT apply → PERMISSION_DENIED (채널에 안 보냄). 같은 call_id의 propose/apply/build/test는 재실행하지 않음.
5. **하니스** `InMemoryLocalAgentChannel` — Phase 1 도구명 `system.ping`, `system.get_capabilities`, `workspace.read_file`, `workspace.propose_changes`. 메모리 파일만.
6. **루프** `AgentWorkflowLoop` — Senior 설계 → 설계 승인 → Implementation propose → Review → WAITING_CODE_APPROVAL.

설계 context가 이미 있으면 WAITING 진입 시 stub DESIGN으로 덮지 않는다.

#### 주요 파일

| 구분 | 경로 |
