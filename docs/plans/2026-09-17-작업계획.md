## 아키텍처 갭 — 전송 결정 (2026-09-17)

DoD를 닫으려면 **Local Agent가 서버에 work item을 넘기고 승인·진행 이벤트를 받을 경로**가 필요하다. Phase 2는 IDE가 없어서 인프로세스 하니스로 대체했다.

홉은 둘이고 서로 다른 ADR이다.

```text
IDE  ↔  Local Agent     ADR-004  localhost WebSocket + JSON   (슬라이스 1)
Local Agent  ↔  Server  ADR-003  gRPC bidirectional streaming (슬라이스 2)
```

ADR-003 확정:

```text
onCode Tool Protocol   ← 논리 계약 (전송과 동일시하지 않음)
        ↓
Transport Adapter      ← 핸들러는 여기만 본다 (기존 Go `transport.Transport`)
        ↓
gRPC                   ← 지금 구현하는 물리 전송
```

- **구현할 것:** gRPC 어댑터 하나. Local Agent가 outbound persistent stream을 연다.
- **구조만 유지:** 도구 핸들러·워크플로를 gRPC 생성 타입에 묶지 않는다. 나중에 WebSocket Adapter를 **같은 인터페이스에** 붙일 수 있으면 된다.
- **지금 하지 않음:** Server↔Agent WebSocket, HTTP JSON 임시 전송, IDE→서버 직접 호출.
- IDE가 서버 REST를 직접 호출하는 경로는 **불가** (SPEC-07 §7).

오늘(슬라이스 1)은 서버 gRPC를 열지 않는다. 슬라이스 2에서 gRPC 어댑터를 붙인다. 테스트용 인메모리 `transport.Memory`는 유지한다.

Phase 2 V1/V2 DDL, Local Agent 도구 재설계, 실 vLLM은 이 갭을 핑계로 열지 않는다.

- 증상: 코드 승인 창이 뜬 직후 서버 `UnexpectedRollbackException` (`ApprovalIntake.bindDiff`). IDE 모달이 안 닫히거나 다시 뜸.
- 원인: `requireUsable`(@Transactional)이 던진 런타임 예외를 `bindDiff`가 잡아 Rejected로 바꾸면 트랜잭션이 rollback-only인 채로 commit을 시도함. 예외가 gRPC `onNext`로 새면 스트림이 끊김.
- 조치: `requireUsable`에 `noRollbackFor` 조회 예외. 컨텍스트 부재는 예외 없이 Optional. gRPC 핸들러가 예외를 이벤트로 바꿈. IDE는 같은 승인을 중복 모달하지 않음.
