# onCode Tool Protocol

Language-independent contract for onCode Tool Protocol v1.

Runtime components (Local Agent, server, IDE) consume these schemas. This package does not implement tool handlers.

```text
protocol/
├─ ids/                 ID kinds, UUIDv7 generation, validation
├─ errors/              structured error model + code catalog
├─ versioning/          oncode-tool/1.x
├─ messages/            Go DTOs matching JSON Schema
├─ schemas/json/        JSON Schema (source for review/tests)
├─ schemas/proto/       protobuf for Server ↔ Local Agent gRPC
└─ tests/fixtures/      shared contract fixtures
```

Current protocol string: `oncode-tool/1.0`

JSON is the logical protocol. protobuf is a transport adapter for the same fields. Do not treat an LLM-generated diff as a protocol object; `ActualDiff` is produced by the Local Agent.

JSON Envelope uses a single `payload` object. The `.proto` adapter maps that payload to typed messages (`ToolRequestPayload`, `ToolResponsePayload`, …). Unstructured objects (`arguments`, `result`, `details`) become `*_json` string fields on the wire. Field *names* stay snake_case via `json_name`.

## Identifiers

Format: `{PREFIX}-{UUIDv7}`

UUIDv7 is RFC 9562 (time-ordered, opaque). Prefixes:

| Kind | Prefix | Field |
|------|--------|-------|
| Message | `MSG` | `message_id` |
| Call | `CALL` | `call_id` |
| Session | `SES` | `session_id` |
| Project | `PRJ` | `project_id` |
| Workspace | `WS` | `workspace_id` |
| Work item | `WI` | `work_item_id` |
| Workflow | `WF` | `workflow_id` |
| Approval | `APR` | `approval_id` |
| Change set | `CHG` | `change_set_id` |
| Task | `TASK` | `task_id` |
| Execution | `EXEC` | `execution_id` |

IDs are generated by the issuing component and must not be reused. Envelope `workspace_id` is optional in SPEC-01 examples and required whenever a workspace-scoped tool is called.

## Versioning

- Advertise `protocol: "oncode-tool/1.0"`.
- Peers must reject an unknown or major-incompatible version (`PROTOCOL_VERSION_UNSUPPORTED`).
- Minor 1.x additions are ignorable by 1.0 readers.
- Breaking changes require `oncode-tool/2.0`.
